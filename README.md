# 班级共享书架——图书借阅管理网站

《Internet应用开发》（23306046）作业一：动态网站开发。

## 当前状态

已完成仓库初始化、需求设计和 JavaScript 版 Next.js 项目骨架。图书目录首页已有可交互的搜索和分类筛选，当前书目仍是页面中的演示数据；登录、数据库读写和真实借还流程尚未实现。

## 需求分析

### 使用场景与目标

班级共享书架的图书由同学共同使用，依靠口头或聊天记录管理时，不容易了解图书是否可借、由谁借走以及何时应归还。本项目计划通过动态网站管理图书信息与借阅记录，完成查询、借出、归还的完整流程。

### 用户角色

- 普通读者：登录、查询图书、借阅可用副本、查看自己的借阅记录。
- 管理员：维护图书与实体副本、查看全部借阅记录、确认归还。
- 未登录访客：可浏览图书目录与详情，借阅前需登录。

### 第一版功能与验收标准

| 功能 | 计划内容 | 验收标准 |
| --- | --- | --- |
| 登录与权限 | 区分读者与管理员，支持退出登录 | 未登录不能借书；读者直接请求管理接口也会被拒绝 |
| 图书查询 | 图书列表、详情、按书名/作者搜索及分类筛选 | 搜索与筛选结果符合条件；无结果时显示提示 |
| 馆藏维护 | 管理员新增、修改图书，新增副本与设置下架 | 保存后刷新仍可读取；副本编号唯一；借出副本不能直接下架 |
| 借阅 | 读者选择可借副本，生成借阅与应还日期 | 无可借副本时拒绝借阅；同一副本同时只能有一条未归还记录 |
| 归还 | 管理员核对实体书后确认归还 | 写入归还时间并恢复可借状态；重复归还不会重复修改记录 |
| 我的借阅 | 展示本人当前借阅及历史记录 | 读者不能读取其他人的私人借阅记录；已还记录保留 |
| 逾期提示 | 根据应还时间标记未归还记录 | 超过应还时间且尚未归还时显示逾期；归还后不再列入当前逾期 |

### 业务规则与范围

- 区分“图书信息”和“实体副本”：同一种书可以有多个带独立编号的副本。
- 第一版默认借期为30天，应还时间由服务端计算；不实现续借、预约排队、罚款或支付。
- 借阅成功表示已完成现场领取登记；课程演示通过测试账号模拟这一过程。
- 借出与归还需要保证副本状态和借阅记录同步更新，避免并发请求导致重复借出。
- 有历史记录的图书和副本使用下架方式停用，不直接删除借阅历史。
- 首版使用预置演示账号，不开放注册；密码采用安全散列保存，不存明文。
- 首版不接入学校系统，不处理真实学生隐私数据；展示数据使用演示数据。

## 方案设计

### 技术方案

课程建议 Next.js 或 Nuxt + Prisma + SQLite/MySQL，本项目采用 Next.js + JavaScript + Prisma + SQLite。页面代码位于 `web/`，使用 Next.js App Router；项目依赖通过 npm 管理。SQLite 负责本地持久化，Prisma 负责数据模型和数据库访问。

浏览器负责展示页面与提交操作；服务端负责身份验证、权限检查、输入校验与借还规则；数据库持久化保存图书、副本和借阅记录。关键规则在服务端执行，不只依赖页面按钮限制。

### 页面规划

| 页面 | 主要内容 |
| --- | --- |
| 图书目录 | 搜索、分类筛选、图书卡片及可借数量 |
| 图书详情 | 图书介绍、副本编号、馆藏位置、可借状态与借阅入口 |
| 登录页 | 账号、密码、登录错误提示 |
| 我的借阅 | 当前借阅、应还时间、逾期提示、历史记录 |
| 管理后台 | 图书和副本维护、借阅记录查询、归还确认 |

### 初步数据设计

| 实体 | 主要字段 | 关系 |
| --- | --- | --- |
| User（用户） | ID、账号、姓名、密码散列、角色 | 一个用户对应多条借阅记录 |
| Book（图书） | ID、书名、作者、分类、简介、是否上架 | 一种图书对应多个实体副本 |
| BookCopy（副本） | ID、唯一馆藏编号、图书ID、位置、状态 | 一个副本对应多次历史借阅 |
| Loan（借阅） | ID、用户ID、副本ID、借出时间、应还时间、归还时间 | 关联用户与具体副本 |

副本状态初步分为可借、借出、下架。逾期根据借阅时间计算，不作为副本状态。字段类型、约束、接口及事务实现将在开发前进一步细化。

## 运行说明

环境要求：Node.js 24 LTS 和 npm。启动开发服务器：

```powershell
cd web
npm.cmd run dev
```

然后在浏览器打开 `http://localhost:3000`。首次安装依赖可在 `web/` 目录运行 `npm.cmd install`。后续接入 Prisma/SQLite 时，再补充数据库初始化步骤。依赖和生成文件不提交，配置示例使用 `.env.example`，不包含真实密钥。
